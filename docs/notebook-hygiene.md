# 노트북 위생 — 재현성·버전관리·리뷰

노트북은 "돌아가는 것"과 "믿을 수 있는 것" 사이의 거리가 특히 먼 도구다.
아래는 그 거리를 줄이는 최소한의 습관이다.

## 1. 재현성 — 위에서부터 한 번에 돌아가는가

노트북의 결과는 **셀을 누른 순서**에 좌우된다. 코드는 그대로인데 결과가 다를 수 있다는 뜻이다.

| 증상 | 원인 |
|---|---|
| `In [7]`, `In [3]`, `In [12]` 처럼 번호가 뒤죽박죽 | 셀을 왔다 갔다 실행 → 출력을 믿을 수 없다 |
| 남에게 주니 `NameError` | 지운 셀에서 만든 변수를 아직 커널이 기억 중이었다 |
| 어제와 결과가 다름 | 난수 시드 미고정, 또는 외부 데이터가 바뀜 |

**규칙**
1. 공유·커밋 전에 **Kernel → Restart Kernel and Run All Cells**
2. 셀 번호가 1, 2, 3… 순서인지 눈으로 확인
3. 난수는 시드를 고정 (`np.random.default_rng(42)`)
4. 데이터·모델 파일 경로는 저장소 기준 상대경로로

## 2. 이름 — `Untitled3.ipynb` 문제

파일명은 그 노트북이 무엇인지 알려 주는 **첫 번째 문서**다. 이 저장소의 원본에는
`Untitled` ~ `Untitled6` 이 있었고, 내용을 열어 보기 전에는 무엇인지 알 수 없었다.
(그중 셋은 서로 거의 같은 컨투어 실험이었다.)

* 만들자마자 이름을 붙인다: `04_data_cleaning.ipynb`
* 순서가 있으면 숫자 접두사를 붙인다 — 파일 목록이 곧 목차가 된다
* 공백·특수문자는 피한다. `image 끝 기준으로 자르기.ipynb` 는 CLI 에서 매번 따옴표가 필요하다

## 3. 버전관리 — `.ipynb` 는 JSON 이다

셀 소스뿐 아니라 **출력·실행 카운터·이미지(base64)** 까지 한 파일에 들어간다.
그래서 한 줄만 고쳐도 diff 가 수천 줄이 되고, 그림을 그리면 파일이 수백 KB 씩 늘어난다.

### 선택 ① 출력을 커밋하지 않는다 (일반적인 정석)

```bash
pip install nbstripout
nbstripout --install          # 저장소에 git filter 등록 — 커밋 시 자동으로 출력 제거
```

### 선택 ② 출력을 커밋한다 (이 저장소의 선택)

학습 자료라 GitHub 미리보기에서 결과가 보여야 의미가 있어서 그대로 둔다.
대신 **모든 노트북이 Restart & Run All 상태**이고 시드가 고정돼 있다.

### 어느 쪽이든 함께 제외할 것

```gitignore
.ipynb_checkpoints/    # 주피터 자동 백업 — 원본과 거의 같은 파일이 두 배로 쌓인다
.DS_Store              # macOS 폴더 메타데이터
.idea/                 # JetBrains 설정 (개인 환경)
.venv/
```

> 이 저장소의 원본에는 위 넷이 전부 커밋돼 있었다. `.ipynb_checkpoints/` 에는 본체와 거의
> 같은 노트북 9개가 중복으로 들어 있었다.

## 4. 리뷰 — 텍스트로 보기

JSON diff 는 사람이 읽을 수 없다. `jupytext` 로 `.py` 짝을 만들면 코드 리뷰가 가능해진다.

```bash
pip install jupytext
jupytext --set-formats ipynb,py:percent notebooks/04_data_cleaning.ipynb   # 짝 지정
jupytext --sync notebooks/04_data_cleaning.ipynb                            # 한쪽을 고치면 반대쪽 갱신
```

`py:percent` 형식은 `# %%` 로 셀을 구분하는 평범한 파이썬 파일이라 diff·grep·린터가 전부 통한다.
(이 저장소의 노트북들도 `py:percent` 로 작성한 뒤 변환·실행한 것이다.)

## 5. 노트북에서 코드로 — 졸업 시점

노트북은 **탐색**에 강하고 **운영**에 약하다. 아래가 보이면 `.py` 로 옮길 때다.

* 같은 셀을 복사해 조금씩 고친 것이 3개 이상
* 다른 노트북에서 이 노트북의 함수를 쓰고 싶다
* 스케줄러로 돌려야 한다
* 테스트를 붙이고 싶다

옮기는 방법은 간단하다. 재사용할 함수만 `nbtools/` 같은 패키지로 빼고, 노트북에서는 import 해서 쓴다.
개발 중이라면 자동 반영을 켜 둔다.

```python
%load_ext autoreload
%autoreload 2
```
